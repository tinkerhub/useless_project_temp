## Project Description

### What happens when a banana gets tired of being a banana?

**Enne Kolland Irikkan Patto?** is an AI-powered object life simulator where you show the camera **literally any object** — and that object becomes the main character of its own ridiculous life.

The object gets an identity, a passport, survives immigration, enters a small interactive world, meets humans, makes questionable decisions, develops a personality, builds relationships, faces consequences, and slowly discovers its purpose in life.

And then...

**it dies.**

Not because you lost.

Not because the game ended.

Because apparently even a banana has to deal with mortality.

A banana might become someone's breakfast.

A phone might spend its final days at 2% battery pretending everything is fine.

A pen might become the most important employee in a stationery shop.

A chair might spend its entire life supporting people who never once asked how it was doing.

Every object gets a life.

Every life gets a story.

And every story gets an ending.

**No object gets plot armor. 💀**

---

## The Problem (that doesn't exist)

Human problems are already well documented.

But what about **object problems**?

Nobody asks:

- Is the chair happy?
- Does the banana have career ambitions?
- Why does the pen keep disappearing?
- Does the phone actually enjoy being charged?
- What happens when a spoon develops trust issues?

Nobody investigates these extremely serious matters.

**This is the problem.**

And naturally, we solved it.

---

## The Solution (that nobody asked for)

Simply show the camera an object.

Our unnecessarily complicated government-grade system will then:

1. 📷 **Identify the object**
2. 🪪 **Create its identity**
3. 🛂 **Issue its passport**
4. 🛃 **Send it to immigration**
5. 🗣️ **Interrogate it**
6. 🌍 **Let it enter the world**
7. 🎮 **Let YOU make its decisions**
8. 🤖 **Let AI react to what happens**
9. 🧠 **Remember everything it did**
10. 💀 **Eventually kill it**

The object's personality, abilities, weaknesses, opportunities and possible future are generated around **what the object actually is**.

So the same world can produce completely different lives.

Show us a banana.

You might get a snack.

Show us a phone.

You might get a criminal.

Show us a chair.

You might get a CEO.

We genuinely don't know.

**And neither do you.**

The object cannot escape Step 10.

We tried.

# Implementation

## For Software

### Installation

```bash
git clone https://github.com/mrmalayali555/Enne-Kolland-Irikkan-patto.git
cd Enne-Kolland-Irikkan-patto
npm install
```

### Environment Variables

Create a `.env` file in the project root and add the required API keys:

```env
GEMINI_API_KEY=your_gemini_key
NVIDIA_API_KEY=your_nvidia_key
```

> **Note:** Never commit your `.env` file or API keys to GitHub.

### Run

```bash
npm run dev
```

Then open the local URL provided by Vite.

# How The AI Works

The AI is not simply asked to write a random story about an object.

Instead, each object receives its own evolving **life state**.

This can include:

- Personality
- Abilities
- Weaknesses
- Goals
- Fears
- Relationships
- Owner
- Money
- Memories
- Achievements
- Crimes
- Important events
- Current condition
- Future possibilities

The AI uses this state to generate situations and reactions that are relevant to the object's actual life.

### Example

A banana that spent its life hiding from customers should not suddenly behave like a completely unrelated banana.

A phone that lost its owner should remember that.

A chair that became famous should have consequences from that fame.

**The object remembers.**

And eventually, the accumulated history contributes to its ending.

---

# Object-Specific Gameplay

The game is designed so that the object itself changes the experience.

A banana, phone, pen and chair do not simply receive different names.

They can have different:

- Abilities
- Limitations
- Interactions
- Opportunities
- Risks
- Personalities
- Possible careers
- Relationships
- Ways of surviving
- Ways of dying

This means that the player cannot completely predict what will happen after scanning an object.

**The object is the protagonist.**

Not the player.

Not the AI.

The object.

---

# AI Game Master

The player can make decisions during the object's life.

The game can provide choices, but the player can also interact through free-form actions.

For example:

```text
Player:
"I hide behind the apple."

AI:
The banana disappears behind the apple display.

Unfortunately, the customer has already picked up the apple.

You have approximately three seconds to reconsider your life choices.
```

The AI evaluates the action against the object's abilities, current state and surroundings.

The world then changes accordingly.

---

# Immigration

Before entering its new life, every object has to pass through immigration.

The immigration system is intentionally designed like serious bureaucracy dealing with a completely ridiculous applicant.

The officer can ask questions such as:

```text
"Why are you entering the country?"

"Who owns you?"

"Do you have anything to declare?"

"Why should we believe you are not a human?"

"Where were you manufactured?"

"Have you ever committed a crime?"
```

The player can respond in:

- English
- Malayalam
- Manglish

The officer reacts to the actual answer instead of simply selecting a predetermined response.

Because apparently even a banana needs to convince immigration that it is not secretly a human.

---

# Major Life Events

Not every moment of the game needs a cinematic.

Most gameplay happens instantly through the interactive world.

When something particularly important happens, the system can use AI-generated cinematic video to represent the major event.

Examples could include:

- Being bought
- Losing an owner
- Becoming famous
- Getting damaged
- Finding a new purpose
- A major relationship
- A ridiculous career achievement
- The object's final moments

The video system is designed to complement gameplay rather than replace it.

**The game is playable.**

The cinematic is the unnecessary dramatic overreaction.

---

# Death System ☠️

There is one rule that cannot be negotiated:

## Every object eventually dies.

The exact ending is not necessarily the same for every object.

Its history, condition, decisions and circumstances can influence how its life ends.

An object could be:

- Used until it breaks
- Lost
- Replaced
- Destroyed
- Eaten
- Retired
- Forgotten
- Recycled
- Or somehow become famous before disappearing

The ending is part of the object's story.

There is no traditional **Game Over**.

There is a **Life Over**.

---

# Final Life Summary

When the object finally reaches the end of its life, the game produces a final life record.

The summary can include things such as:

```text
THE LIFE OF BANANA #017

Origin: Kerala
Occupation: Emergency Snack
Owner: Appukkuttan

Friends: 3
Enemies: 5
Crimes: 7
Money Earned: ₹47

Days Survived: 6

Major Memories:
- Survived immigration
- Escaped a fruit shop
- Became famous
- Betrayed an apple

Final Destination:
Appukkuttan's stomach

Cause of Death:
Consumption
```

The point isn't to create a useful database.

It's to give a completely unnecessary amount of documentation to an object that never asked for any of it.
